tryarch

Boot anything Arch Linux ever shipped, in your browser

A real x86_64 Linux guest runs in this tab — QEMU compiled to WebAssembly, with nothing on a server. Pick official Arch packages from core and extra, or an older version from the Arch Linux Archive on archive.org, and you get a shell with them on PATH. Every version links to the PKGBUILD it was built from.

Try

  • jq
  • jq 1.5, from 2015
  • python
  • vim
  • bash 5.1.016-1
Pick

Every package name in core and extra for x86_64, from the repository databases.

One spec per package, each resolved on its own to the newest version that matches; pacman's own form (jq>=1.6) works too. Versions that never shipped together still boot together — each package brings its own dependencies.

Any pacman repository database whose host allows cross-origin reads. Its packages win over the official repos, and the URLs ride in this page's link with the selection.

example: hello-tryarch, a one-file package served next to this page.

reboot with this selection

Packages added to a running VM appear in the shell straight away; when two provide the same command, the one written first wins — a file already in the share is never overwritten. A command the shell has already run once is remembered at its old path until hash -r.

About

        

          
How it works

          

            The page fetches a kernel, an initramfs and a resumable QEMU snapshot, then runs
            qemu-wasm in a worker. The packages you pick are downloaded and unpacked into the
            browser's own in-memory filesystem and handed to the guest over virtio-9p as
            /share, which the guest's init dresses up as an Arch root —
            /usr, /lib, /etc and a shell on
            PATH. Resuming the snapshot skips the kernel's start-up, so the prompt
            arrives in seconds rather than a minute.
          


          
Where the bytes come from

          

            Current packages come from the five Arch mirrors that allow cross-origin reads —
            mirror.lcarilla.de, archlinux.mailtunnel.eu,
            repo.c48.uk, mirror.iusearchbtw.nl and
            yonderly.org — tried in that order, with the repository database from
            the same place. Older versions come from the Internet Archive's mirror of the Arch
            Linux Archive, one item per package name, read through archive.org's CORS endpoint.
          

          

            That mirror stops around October 2024. A version that was still current then,
            or older, is there; a version that came and went after that date is not, and
            archive.archlinux.org — which does have it — sends no CORS headers, so
            no page can read it. Those versions are missing from the version list altogether,
            not listed and unbootable: the list is what the archive holds, plus whatever is
            current now.
          


          
What is checked

          

            A package from a mirror is verified against the SHA-256 in the repository database; a
            package from archive.org against the SHA-1 in its metadata. PGP signatures are
            not checked — the database and the package come from the same host, so the
            hash proves the transfer, not the packager. What runs is a guest in your tab with no
            network and no access to your machine, which is what makes that a reasonable trade
            here and not in a package manager.
          


          
Limits

          
    
            
  • 
              .INSTALL scriptlets are never run, so a package that needs
              post-install work (users, caches, systemd units) arrives unconfigured.
            
    • 
            
  • 
              Only packages present at boot get their /etc copied into the guest;
              anything added later keeps its files under /share/etc.
            
    • 
            
  • 
              AUR packages are recipes, not binaries — there is nothing to fetch, so they cannot
              be booted. pkglint grades those
              instead.
            
    • 
            
  • multilib is skipped; only x86_64 and any packages.
    • 
            
  • 
              The unpacked tree lives in memory: about 1.2 GB of files at most, with 512 MB of
              RAM in the guest.
