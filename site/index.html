tryarch

Boot any Arch package
ever shipped, in a browser

A real x86_64 Linux machine — QEMU compiled to WebAssembly — runs in this tab, with nothing on a server. Pick packages from core and extra, or an older version from the Arch Linux Archive, and you get a shell with them on PATH.

How it works — the machine, the mirrors, what is checked, and why the archive stops in October 2024.

Pick

Every package name in core and extra for x86_64, from the repository databases.

One spec per package, each resolved on its own to the newest version that matches; pacman's own form (jq>=1.6) works too. Versions that never shipped together still boot together — each package brings its own dependencies.

Any pacman repository database whose host allows cross-origin reads. Its packages win over the official repos, and the URLs ride in this page's link with the selection.

example: hello-tryarch, a one-file package served next to this page.

A recipe is built by makepkg inside the guest, and the package it makes is unpacked like any other. Every AUR recipe is here by name; any PKGBUILD by URL. The page gathers the sources before the boot, because the guest has no network: what a host will not serve to a page, download yourself and drop on the row. Nothing compiles fast under an emulator — a -bin package or an any one builds in under a minute, a C program in many.

example: hello-tryarch, the same recipe the example repository was built from, built in the guest instead.

reboot with this selection

Packages added to a running VM appear in the shell straight away; when two provide the same command, the one written first wins — a file already in the share is never overwritten. A command the shell has already run once is remembered at its old path until hash -r.
